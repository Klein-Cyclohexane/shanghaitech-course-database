1. Search — Problem Definition

State: configuration of the world. Start state: initial. Goal state(s): desired. Successor fn: state→(action,next_state,cost). Path cost: cumulative edge costs.

Completeness: finds solution if one exists. Optimality: finds minimum-cost solution.

Ex. 8-Puzzle: State = tile arrangement. Total states = 9! = 362880. Max branching = 4 (blank in center). Goal = tiles 1–8 in order top-left to bottom-right.

⚠ UCS*: complete only if min arc cost ε > 0 (not ≥0). Zero-cost edges → may loop.

⚠ DFS: space advantage O(bm) — only stores current path. Not complete on infinite/cyclic graphs.
3. Heuristic Functions
f(n) = g(n) + h(n) [A* evaluation fn] g(n) = actual cost start→n h(n) = estimated cost n→goal
Admissible
h(n) ≤ h*(n)

Never overestimates. Guarantees A* tree-search optimality.

Consistent (Monotone)
h(n) ≤ c(n,n') + h(n')

Triangle inequality. Guarantees A* graph-search optimality.

⚠ Consistent ⟹ Admissible; reverse NOT true.
⚠ h(n)=0 always admissible; UCS = A* with h=0.
⚠ Admissible but NOT consistent: tree-search OK, graph-search may fail.
⚠ Dominant: h₂≥h₁ for all n → h₂ expands ≤ nodes than h₁.
8-Puzzle heuristics: h₁=misplaced tiles ✓admissible ✓consistent. h₂=Manhattan distance ✓✓. h₃=inversion count ✗ not admissible, ✗ not consistent (can overestimate).
4. A* Search Algorithm
A*(problem): fringe = PriorityQueue ordered by f(n)=g(n)+h(n) closed = {} (graph search only) push start node (g=0) while fringe not empty: n = pop (smallest f) if goal(n): return solution if n.state not in closed: // graph search closed.add(n.state) expand n, push children with updated g,f
Tree-search + admissible h → optimal. Graph-search + consistent h → optimal + complete.
Ex. Admissible/Consistent check: Given h: S=6,A=5,B=5,C=4,D=2,G=0. Edge S→A cost 1. Check admissible: compute true shortest paths. Check consistent: for each edge (n,n'), verify h(n)≤cost(n,n')+h(n'). If S→A costs 1: h(S)=6≤1+5=6 ✓. If A→C costs 2: h(A)=5≤2+4=6 ✓.
5. CSP — Definition & Backtracking

Variables X₁…Xₙ; Domains D₁…Dₙ; Constraints C. Goal: complete assignment satisfying all constraints.

Backtrack(assignment, csp): if complete: return assignment X ← SelectVar(csp, assignment) for v in OrderValues(X, assignment, csp): if consistent(v, assignment): assignment[X] = v result ← Backtrack(assignment, csp) if result ≠ failure: return result del assignment[X] return failure
Ex. Course scheduling: After unary constraints applied to all vars, C∈{6,10}, S∈{1,3,5,7,9}, P∈{4,6}, F∈{3,4}, G∈{2,4,6,8,10}, B∈{1,5}. Assign C=10 first (domain size 2 = MRV along with others).
6. Filtering Strategies
Forward Checking (FC)

After X=v, remove from each unassigned neighbor Y any value inconsistent with v. If any domain empties → backtrack.

Arc Consistency — AC-3

Arc (X,Y) consistent: ∀ x∈D(X), ∃ y∈D(Y) compatible. AC-3 makes ALL arcs consistent.

AC-3: Q = all arcs (Xi,Xj) in CSP while Q not empty: (Xi, Xj) = dequeue(Q) if Revise(Xi, Xj): // removed from D(Xi) if D(Xi) empty: return FAILURE for each Xk ≠ Xj neighbor of Xi: enqueue (Xk, Xi)
⚠ Arc (X,Y): removes values from X's domain, not Y's.
⚠ After X shrinks, re-add arcs (Z,X) for all Z neighboring X.
⚠ AC-3 stronger than FC: propagates further than just direct neighbors.
7. Ordering Heuristics
MRV (Variable Selection)

Minimum Remaining Values: pick variable with fewest legal values left. "Most constrained first." Fail early, backtrack early.

Ex. Domains: A:{R,G}, B:{R}, C:{R,G,B} → choose B (1 value = most constrained).
LCV (Value Selection)

Least Constraining Value: for chosen variable, pick value eliminating fewest values from neighbors. Preserve flexibility.

Ex. X=R eliminates 3 neighbor values; X=B eliminates 1 → choose B (least constraining).
⚠ MRV picks variable (most constrained). LCV picks value (least constraining). Don't confuse!
8. Structure Methods
Tree-Structured CSP — O(nd²)

If constraint graph is a tree (no undirected cycles):

  1. Pick root, compute topological order
  2. Backward pass (leaf→root): Revise each arc (parent,child) — remove inconsistent parent values
  3. Forward pass (root→leaf): assign each variable consistently with already-assigned parent
Ex. Chain A-B-C-D. Backward: make arcs (C,D),(B,C),(A,B) consistent. Forward: assign A→B→C→D.
Cutset Conditioning

Find cycle cutset S: removing S leaves a tree. Min cutset = smallest such S.

  1. Find cutset S (size c)
  2. Enumerate all d^c assignments of S
  3. For each, solve remaining tree in O((n-c)d²)

Total: O(d^c · nd²). Efficient when c small.

⚠ Min cutset: fewest variables s.t. removal makes graph a tree.
⚠ Tree check: count edges vs nodes (tree ↔ |E|=|V|-1, connected). Or check undirected cycles.
9. Local Search for CSP
  • Min-Conflicts: start with random assignment; repeatedly pick conflicted variable, assign value minimizing #violated constraints.
  • Hill Climbing: move to best neighbor. Stuck in local optima, plateaus, ridges.
  • Simulated Annealing: accept worse moves with prob e^(ΔE/T), T decreasing → escapes local optima.
  • Genetic Algo: Selection (fitness) → Crossover (combine parents) → Mutation (random change).
⚠ Genetic algo order: crossover first, mutation second!
⚠ Min-conflicts: count #violated constraints for CURRENT full assignment per variable.
Ex. Min-conflicts count: Assignment C:6,S:8,P:2,F:3,G:4,B:5. S=8 violates: (ii) S must be AM→8 is PM ✗; (viii) S before C: 8>6 ✗. Count = 2 violations for S.
10. Minimax Algorithm

Zero-sum game: MAX agent maximizes, MIN agent minimizes. Assumes perfectly rational opponent.

Minimax(s, player): if terminal(s): return utility(s) if player=MAX: return max over successors c: Minimax(c, MIN) if player=MIN: return min over successors c: Minimax(c, MAX)

Time: O(b^m)   Space: O(bm)   (identical to DFS)

⚠ Time = O(b^m) NOT O(b·m) or O(b·d)!
⚠ Zero-sum: utilities OPPOSITE (not independent). "Independent" → FALSE.
⚠ Standard minimax fails on cyclic graphs (infinite loops).
⚠ Minimax ≠ Expectimax. Minimax: opponent rational. Expectimax: chance/random.
Ex. Range of X (Fig.2a): Left MIN b: children MAX c={1,7}→7, MAX d={X,5}→max(X,5). b=min(7, max(X,5)). Root MAX a=max(b, right_sub). For a to choose branch through e→f (value = max(X,5)), need max(X,5) > other_branch_val=2. So max(X,5)>2 always. But for X to BE root value: need X>5 (so max(X,5)=X) AND X>7 (beats other subtree). Range: 7 < X ≤ 10.
11. Alpha-Beta Pruning

α (alpha): best (highest) value MAX can guarantee on path to root. Starts −∞, only increases.
β (beta): best (lowest) value MIN can guarantee on path to root. Starts +∞, only decreases.

Prune at MIN node

Current value ≤ α → prune rest. MAX already has ≥α elsewhere, won't choose this.

Prune at MAX node

Current value ≥ β → prune rest. MIN already has ≤β elsewhere, won't choose this.

AlphaBeta(s, α, β): if terminal: return utility(s) if MAX: v=-∞ for c in children(s): v=max(v, AB(c, α, β)) if v≥β: return v // β-prune (MIN won't choose) α=max(α,v) if MIN: v=+∞ for c in children(s): v=min(v, AB(c, α, β)) if v≤α: return v // α-prune (MAX won't choose) β=min(β,v) return v
⚠ Node order critically affects pruning! Best case O(b^(m/2)), worst O(b^m).
⚠ Good order: evaluate best moves first → set tight α/β bounds early → more pruning.
⚠ Reversing leaf order usually reduces pruning count.
⚠ Result = same as minimax, just faster.
Ex. Prune l (Fig.2b): Evaluate k,m,n normally. Need Y such that at the point of evaluating l, the β bound at l's parent is ≤ some value. Tracing: i subtree gives value≥some threshold. If j subtree (parent MAX h) already has a value making α≥l's MIN subtree result → l pruned. The constraint works out to: 0 ≤ Y ≤ 2.
12. Expectimax & Chance Nodes
Expectimax(chance_node) = Σᵢ P(childᵢ) × Expectimax(childᵢ)
⚠ Expectimax assumes opponent is non-rational / random (not adversarial).
⚠ Changing probability distribution invalidates pruning — cannot reuse same pruning!
⚠ Bounded values [a,b] needed for chance node pruning.
Ex. F23 Q3.2: Left chance: 0.5×min(2,2)+0.5×min(1,2)=0.5×2+0.5×1=1.5. Right chance: 0.5×min(0,2)+0.5×min(−1,0)=0+0.5×(−1)=−0.5. Root MAX: max(1.5,−0.5)=1.5 → choose Left.
13. Multi-Agent Non-Zero-Sum

Each player maximizes own utility (different objectives). Utilities = tuples (A-val, B-val, C-val). Each layer: that player picks child maximizing their own component.

Coalition: allied players pick child maximizing their sum of utilities.

⚠ Coalition does NOT always increase individual utilities — may sacrifice one member for total gain. Answer: "Does coalition always guarantee higher utility?" → NO.

⚠ Valid ≠ Satisfiable! Valid = ALL models. Satisfiable = SOME.
⚠ "Satisfiable if true in all models" → FALSE (that's valid!)

Key equivalences:

15. CNF Conversion (4 Steps)
  1. Eliminate ⟺: A⟺B → (A⇒B)∧(B⇒A)
  2. Eliminate ⇒: A⇒B → ¬A∨B
  3. Push ¬ inward: ¬(A∧B)→¬A∨¬B; ¬(A∨B)→¬A∧¬B; ¬¬A→A
  4. Distribute ∨ over ∧: A∨(B∧C)→(A∨B)∧(A∨C)
Ex. (B∧C)∨(A∧B)⇒D: Step2: ¬[(B∧C)∨(A∧B)]∨D. Step3: (¬B∨¬C)∧(¬A∨¬B)∨D. Step4: (¬B∨¬C∨D)∧(¬A∨¬B∨D).
Ex. (A∧C∧D)∨C⇒B: Step2: ¬[(A∧C∧D)∨C]∨B. Step3: (¬A∨¬C∨¬D)∧¬C∨B. Step4: (¬A∨¬C∨¬D∨B)∧(¬C∨B). (Simplify: ¬C∨B subsumes ¬A∨¬C∨¬D∨B when ¬C true.)
16. Resolution & Resolution Refutation
Resolution Rule: (ℓ₁∨…∨P) and (¬P∨m₁∨…) ────────────────────────── (ℓ₁∨…∨m₁∨…) If result = □ (empty clause) → contradiction!

Refutation: to prove KB⊨α, add ¬α to KB, convert to CNF, resolve until □.

Ex. Prove D from {A∨B, ¬A, C, ¬B∨¬C∨D, ¬A∨¬B∨D} Add ¬D: (A∨B) + (¬A) → B B + (¬B∨¬C∨D) → ¬C∨D (¬C∨D) + (¬D) → ¬C (¬C) + C → □ ✓ proved KB⊨D
⚠ Must add ¬(conclusion) before resolving.
⚠ Can resolve ANY pair with complementary literals.
⚠ CNF result has ONLY ∧ and ∨ and ¬ — no ⇒ or ⟺.
17. Horn Logic & Chaining

Horn clause: at most one positive literal. Form: P₁∧…∧Pₙ⇒Q.

Forward Chaining

Data-driven (bottom-up). Start from facts, fire rules, add conclusions, repeat until goal found or no new facts. Sound & complete for Horn.

Backward Chaining

Goal-driven (top-down). From goal, find rules concluding it, recurse on premises. Stops when all premises are known. May repeat subgoals.

⚠ FC = data-driven. BC = goal-driven (BC is NOT data-driven — common MCQ trap!).
⚠ Modus Ponens: sound & complete for Horn ONLY (not general propositional logic).
⚠ ¬A∨¬B∨C: one positive (C) → Horn ✓. ¬A∨B∨C: two positives → NOT Horn ✗.

19. Quantifiers — The Golden Rules
∀ (Universal) → always use ⇒
∀x Student(x) ⇒ Smart(x)

"For all x, if Student then Smart."

WRONG: ∀x Student(x)∧Smart(x)
→ "Everything is a student AND smart"!
∃ (Existential) → always use ∧
∃x Student(x) ∧ Smart(x)

"There exists smart student."

WRONG: ∃x Student(x)⇒Smart(x)
→ True even if no students exist!
⚠ Quantifier order MATTERS — NOT commutative:
∀x∃y Loves(x,y): Every person loves someone (possibly different for each).
∃y∀x Loves(x,y): There is ONE person loved by everyone. NOT equivalent!
⚠ Useful: ∀xP(x)≡¬∃x¬P(x); ∃xP(x)≡¬∀x¬P(x).

21. FOL — Models & Semantics

A model in FOL specifies: (1) domain of objects, (2) interpretation mapping constants→objects, functions→functions on objects, predicates→relations on objects.

Sentence is true in a model under an assignment of variables.

KB⊨α: α is true in every model where KB is true (same as propositional).

If α entailed by any subset of KB → α entailed by KB. Adding knowledge cannot destroy entailments.
Ex. Checking "is Paimon right?" KB = {Fontaine(BW), Own(BW,Sinthe), Toxic(Sinthe), rule1(drink+toxic→unconscious), rule2(Fontaine+own+attractive→drink)}. Missing: Attractive(Sinthe). Without it: cannot derive Drink(BW,Sinthe) → cannot derive Unconscious(BW). Paimon is correct — info insufficient!
22. Instantiation Rules
Universal Instantiation (UI)
From ∀x P(x): derive P(c) for any constant c Ex: ∀x Mortal(x) → Mortal(Socrates), Mortal(John), …
Existential Instantiation (EI)
From ∃x P(x): derive P(K) where K is NEW Skolem constant Ex: ∃x Crown(x) → Crown(C₁) (new constant)
⚠ EI: use a BRAND NEW constant not appearing elsewhere. Cannot reuse existing constants.
23. Unification

Find substitution σ making two expressions identical.

Unify(Knows(John,x), Knows(John,Jane)) = {x/Jane} Unify(Knows(x,Bob), Knows(y,Bob)) = {x/y} or {y/x} Unify(Knows(x,y), Knows(y,John)) = {x/John, y/John} Unify(P(x), P(f(x))) → FAIL (occur check: x in f(x))

MGU (Most General Unifier): least committal unifier (fewest bindings).

⚠ Cannot unify different constants: John ≠ Mary (constants are fixed).
⚠ Occur check: don't unify x with term containing x → infinite structure.
24. FOL Forward & Backward Chaining

Same as propositional but with variable unification.

Forward Chaining (data-driven)
  1. Start with known ground facts in KB
  2. Find rules whose body unifies with known facts
  3. Add unified head as new fact
  4. Repeat until goal found or no new facts added
Backward Chaining (goal-driven)
  1. Start with goal query
  2. Find rules whose head unifies with goal
  3. Subgoals = unified body predicates
  4. Recurse; succeed if all subgoals provable from KB
Ex. FC to prove Unconscious(BigWei):
KB: Fontaine(BW), Own(BW,Sinthe), Toxic(Sinthe), Attractive(Sinthe),
Rule1: Fontaine(x)∧Own(x,y)∧Attractive(y)⇒Drink(x,y)
Rule2: Drink(x,y)∧Toxic(y)⇒Unconscious(x)
FC: unify Rule1 with {x/BW,y/Sinthe} → Drink(BW,Sinthe).
Unify Rule2 with {x/BW,y/Sinthe} → Unconscious(BW). ✓
⚠ FC: sound & complete for FOL Horn. Data-driven.
⚠ BC: sound & complete for FOL Horn. Goal-driven.
⚠ BC may revisit subgoals — use memoization (tabling) to avoid.
25. FOL Resolution
  1. Negate conclusion: KB ∪ {¬α}
  2. Convert to CNF (including Skolemization for ∃)
  3. Resolve: pick two clauses with complementary literals, unify, produce resolvent
  4. Repeat until □ found or no new clauses possible
Skolemization: replace ∃x with Skolem constant (if no ∀ in scope) or Skolem function of universally-quantified vars in scope.
26. FOL — Comprehensive Exam Traps
  • FC is data-driven. BC is goal-driven. "BC is data-driven" → FALSE.
  • ∀xP(x) ≡ ¬(¬∃xP(x)) → TRUE (both say "all x satisfy P").
  • ∀x∃y R(x,y) ≢ ∃y∀x R(x,y) — order matters → NOT equivalent.
  • "Student(x)∧At(x,SHT)∧Smart(x)" with ∀ says everything is a student at SHT who's smart → WRONG.
  • KB⊨α proved by KB∧¬α contradiction, NOT KB∨¬α.
  • If KB has enough chain to conclusion via FC, BC will also find it.
  • If missing ONE premise (e.g. Attractive(Sinthe)), cannot conclude — Paimon right.
  • Atomic sentence: predicate applied to terms. No connectives. >(Height(A),Height(B)) IS atomic ✓.
27. Propositional Logic — Semantic Matching Puzzle

Some exams give logical formulas and ask you to match variables to semantics. Method:

  1. Identify which formula has NO negations and appears alone as a clause → that's a fact (e.g. C)
  2. Identify which variable appears only negated alone → that's the negated fact (e.g. ¬B or ¬D)
  3. Work out which matches "If X then Y" patterns (⇒) vs facts
Ex. F24 Q4.1 (Coach Leo):
Formulas: (¬C∨A)∧(¬C∨D), ¬B∨¬D∨A, ¬C, B∨D
¬C alone → C = "Keep practicing" (negated = not keep practicing, direct fact)
B∨D → "Be strong OR best player" = disjunction of two positives
¬B∨¬D∨A means B∧D⇒A → if best player and practicing then strong
Match: C=keep practicing, A=strong, B=best player, D=drink milk.
28. Resolution Proof — Step-by-Step Template
  1. List all given CNF clauses (KB)
  2. Add ¬(what you want to prove) as new clause(s)
  3. Find two clauses with complementary literals (P and ¬P)
  4. Resolve: remove P and ¬P, combine remaining literals
  5. Add resolvent to clause list
  6. Repeat until □ produced or no more resolutions possible
Ex. F23 Q4.3 complete proof:
KB clauses: (A∨B), (¬A), C, (¬B∨¬C∨D), (¬A∨¬B∨D). Prove D → add ¬D.
1. (A∨B) + (¬A) → B 2. B + (¬B∨¬C∨D) → ¬C∨D 3. (¬C∨D) + (¬D) → ¬C 4. (¬C) + C → □ ✓
Ex. Prove KB⊨¬C∧¬D (F24 Q4.3):
KB has ¬C as fact. Need also ¬D.
From clauses: ¬B∨¬D∨A. With ¬B (from ¬C via rules) and ¬A situation, resolve to get ¬D.
Full trace: use all available clauses systematically.

30. FOL Inference Strategy

Choose inference method based on query type:

  • Propositional query, small KB: truth table or resolution
  • Horn KB, any query: FC (forward) or BC (backward)
  • General FOL, complex query: FOL resolution with unification

Completeness caveat: FOL resolution is complete but may not terminate if KB is inconsistent or query undecidable. Horn FOL FC/BC always terminate for ground atoms.

32. Propositional Logic — Semantic Reasoning Shortcuts
  • If KB has ¬A and (A∨B) → can derive B immediately
  • If KB has C (positive fact) and ¬B∨¬C∨D → add ¬B → get ¬B∨D
  • Check if conclusion negation leads to contradiction with shortest resolution path first
  • Work bottom-up: start from unit clauses (single literals), resolve with larger clauses
Ex. F24 Q4.3 Prove ¬C∧¬D:
KB has ¬C directly as clause → ¬C proven trivially.
For ¬D: clause B∨D; clause ¬B∨¬D∨A; clause ¬C means not-practicing, use implications.
Add ¬(¬C∧¬D)=C∨D. Resolve C∨D with ¬C → D. Then need ¬D → resolve → □. ✓
33. FOL Exam Checklist
  • Every variable must be bound by a quantifier (∀ or ∃) — no free variables in sentences
  • ∀ with ⇒ ; ∃ with ∧ — check every translation
  • Check quantifier order matches intended meaning
  • Identify: is it constant (specific), variable (quantified), function (returns individual), predicate (returns T/F)?
  • Atomic sentence: predicate(terms) only — no logical connectives inside
  • Resolution: add ¬goal, find □
  • FC: start from facts, fire rules forward
  • BC: start from goal, decompose into subgoals

34. Bayesian Network — Definition

Bayesian Network (BN): Directed Acyclic Graph (DAG) where each node = random variable, edges = direct probabilistic dependencies, each node has CPT (Conditional Probability Table) conditioned on parents.

Global semantics (chain rule factorization):

P(X₁,X₂,…,Xₙ) = ∏ᵢ P(Xᵢ | Parents(Xᵢ))

Local semantics: each node is conditionally independent of all its non-descendants given its parents.

Ex. BN: T→F, T→P, M→F, M→P, F→B, P→B (Genshin Impact BN).
P(+t,+m,+f,+p,+b) = P(+t)·P(+m)·P(+f|+t,+m)·P(+p|+t,+m)·P(+b|+f,+p)
= 0.6·0.1·0.4·0.8·0.9 = 0.01728
35. D-Separation — Three Canonical Patterns
① Chain
A → B → C

A⊥C|B: YES (B blocks)
A⊥C: NO (info flows)

② Fork
A ← B → C

A⊥C|B: YES (B blocks)
A⊥C: NO (common cause)

③ Collider
A → B ← C

A⊥C|B: NO (B activates!)
A⊥C: YES (default independent)

⚠ Collider reversal! Observing the collider node B (or any of its descendants) creates A-C dependence ("explaining away" / Berkson's paradox).
⚠ If B's descendant D is observed → also activates the A→B←C path.

D-separation algorithm: A⊥B|E iff ALL undirected paths from A to B are blocked.

A path is blocked if ANY triple along it satisfies:

Triple typeBlocked if…
Chain: X→Y→Z or X←Y→Z (Fork)Middle node Y ∈ E (observed)
Collider: X→Y←ZY ∉ E AND no descendant of Y ∈ E
Ex. T→F←M (Fork at T,M for F; Collider at F for T,M). Is T⊥M|F?
Path T→F←M: collider at F. F∈E (observed) → NOT blocked → T not ⊥M|F.
Is T⊥M? Path T→F←M: collider at F, F∉E → blocked. No other path. → T⊥M: YES.
36. Markov Blanket
MB(X) = Parents(X) ∪ Children(X) ∪ OtherParents(Children(X))

Given MB(X), X is conditionally independent of ALL other variables in the network. Used in Gibbs sampling.

Ex. BN: A→B, C→B, A→D, B→D. Find MB(A).
Parents(A)={}. Children(A)={B,D}. OtherParents(B)={C}. OtherParents(D)={B}.
MB(A) = {} ∪ {B,D} ∪ {C,B} = {B,C,D}.
⚠ Don't forget "co-parents" = other parents of X's children. Very commonly missed!
⚠ MB of a root node (no parents) = its children + co-parents of children.
37. Conditional Independence Assertions

Claim: P(A|B)=P(A|B,C) ↔ A⊥C|B. Use d-separation to verify.

Ex. F23 BN: T→F,T→P,M→F,M→P,F→B,P→B. Three assertions:
1. P(T,F,M)=P(T)P(F)P(M)? Requires T,F,M mutually independent. Path T→F←M: collider F, F not obs → blocked. Path T→P←M: collider P, not obs → blocked. No T-M path otherwise. So T⊥M ✓. But T⊥F? Path T→F: direct edge → NOT independent. FAILS → NO.
2. P(T|B)=P(T|B,M)? T⊥M|B? Paths T→F→B←P←M: B is collider-descendant here? B is obs. Path T→F→B: chain, B obs? Actually F→B←P: F→B collider at B, B obs → activates T→F→B←P←M path. → T not ⊥M|B. NO.
3. P(F|T,M)=P(F|T,M,P)? F⊥P|T,M? Path F←T→P: T∈E → blocked. Path F←M→P: M∈E → blocked. All paths blocked. → YES.
38. Polytree

Polytree: BN where the underlying undirected graph has no cycles (is a tree/forest). Direction ignored for cycle detection.

⚠ ALL BNs are DAGs (no directed cycles). Polytree is stronger: no undirected cycles either.
⚠ Polytrees allow more efficient exact inference (no need to handle loops in message passing).
Ex. BN T→F, T→P, M→F, M→P, F→B, P→B:
Undirected edges: T-F, T-P, M-F, M-P, F-B, P-B. Undirected cycle: T-F-B-P-T. → NOT polytree.
Polytree example: A→B→D, A→C (simple tree structure) → polytree ✓.
39. Exact Inference — Enumeration
P(Q|e) = α · Σ_{hidden h} P(Q,e,h) = Σ_{h} P(Q,e,h) / Σ_{Q,h} P(Q,e,h) Use BN factorization to compute each P(Q,e,h): P(Q,e,h) = ∏ᵢ P(Xᵢ|Parents(Xᵢ)) for all variables
Ex. P(+b|+t,−m,−p): P fixed, F is hidden.
= [P(+b|+f,−p)·P(+f|+t,−m) + P(+b|−f,−p)·P(−f|+t,−m)] / P(+t,−m,−p)
Since P is evidence (−p), F is hidden. Numerator only.
= 0.1×0.1 + 0.0×0.9 = 0.01
40. Variable Elimination (VE)

Eliminate hidden variables one at a time. Each elimination: collect all factors containing that variable → join (pointwise multiply) → sum out the variable.

Algorithm to compute P(Q|e): 1. Start with all CPTs as factors 2. Fix evidence: restrict factors to evidence values 3. For each hidden variable Z (in chosen order): a. Collect all factors f₁,…,fₖ mentioning Z b. New factor = Σ_Z (f₁ × f₂ × … × fₖ) [join+sum] c. Add new factor to factor list 4. Multiply remaining factors, normalize
Ex. Factor operations:
P(A|B) × P(B) = P(A,B)   [join on B]
Σ_B P(A,B) = P(A)   [sum out B]
P(A|C) × P(B|A,C): join → P(A,B|C) [both mention A]
P(A|B) × P(C|A,B) × P(B) → join all on B → Σ_B → P(A,C)
⚠ Factor size = #rows = 2^(#variables in factor) for binary vars. Large factors = slow.
⚠ Elimination order matters: good order = small intermediate factors.
⚠ Largest factor exam question: simulate each ordering, track max factor size at each step.
Ex. F23 Q5.1.4: Find ordering with largest max factor to compute P(+b).
Orderings considered: P,T,F,M and F,P,M,T both create a factor involving {T,M,F,P} (4 vars = 16 rows) as intermediate. These are the worst orderings. Answer: AD (P,T,F,M and F,P,M,T).
41. Computing Probabilities — Pattern

For P(+a,+b,+d) in BN A→B, C→B, A→D, B→D:

P(+a,+b,+d) = Σ_c P(+a)·P(c)·P(+b|+a,c)·P(+d|+a,+b) = P(+a)·[P(+c)P(+b|+a,+c)+P(−c)P(+b|+a,−c)]·P(+d|+a,+b) = 0.05·[0.3·0.65+0.7·0.15]·0.60 = 0.05·0.300·0.60 = 0.009
Always check: which vars are in numerator (query+evidence), which are marginalized (hidden). Apply chain rule via BN structure.
42. Markov Networks

Markov Network (Undirected Graphical Model): undirected graph + potential functions ϕ over cliques.

P(x) = (1/Z) · ∏_c ϕ_c(x_c) Z = Σ_x ∏_c ϕ_c(x_c) [partition/normalization constant]

Potentials ϕ: non-negative functions (NOT probabilities themselves).

⚠ Potentials don't sum to 1. Z normalizes.
⚠ Cannot read conditional probabilities directly from potentials (unlike BN CPTs).

Independence in Markov Net: A⊥B|S iff S separates A from B (removing S nodes disconnects A from B in graph).

Ex. Markov net: A-C-B chain. A⊥B|C? Remove C: A,B disconnected → YES.
4-node square A-B-C-D all connected: A⊥C|B,D? Remove B,D: A and C disconnected → YES.
43. Cliques & Maximal Cliques

Clique: subset where every pair of nodes is connected. Maximal clique: cannot add any more nodes.

Ex. F23 Q10: Markov net A,B,C,D; edges A-C, A-D, B-C, B-D, C-D.
{A,C,D}: all pairs connected (A-C✓,A-D✓,C-D✓). Can add B? B-A? No edge → can't. Maximal: {A,C,D}.
{B,C,D}: B-C✓, B-D✓, C-D✓. Can add A? A-B? No. Maximal: {B,C,D}.
A,C,D is indeed a maximal clique ✓.
Compute P(+a,+b,+c,+d):
= ϕ(+a,+c,+d)×ϕ(+b,+c,+d) / Z = 10×40/Z.
Compute Z = sum over all 16 assignments of ϕ(A,C,D)×ϕ(B,C,D).
Z = (10+20+30+40)×? Actually: Σ_{a,c,d} ϕ(a,c,d) × Σ_{b} ϕ(b,c,d) — NO, can't factor like this since C,D shared.
Must enumerate: Σ_{a,b,c,d} ϕ(a,c,d)·ϕ(b,c,d). = Σ_{c,d} [Σ_a ϕ(a,c,d)] · [Σ_b ϕ(b,c,d)].
(+c+d): [10+40]·[40+10]=50·50=2500. (+c-d): [20+30]·[30+20]=2500. (-c+d): [30+20]·[20+30]=2500. (-c-d): [40+10]·[10+40]=2500. Z=10000.
P(+a,+b,+c,+d) = 10×40/10000 = 400/10000 = 0.04 ✓
44. BN ↔ Markov Network Conversion

BN → Markov Net (Moralization): for every pair of nodes with common child, add undirected edge between them ("marry co-parents"). Then make all edges undirected.

Markov Net → BN: must capture all clique dependencies. BN that "always encodes same distribution" needs edges for all maximal clique members.

Ex. F23 Q9: Markov net A-D-B-C-A (4-cycle: A connected to B,C,D; etc.).
To encode same distribution, BN needs to capture all dependencies. BN (d) with most complete connections works. Reasoning: Markov net's cliques require BN to have those conditional dependencies — minimal BN missing edges might assert false independence.
⚠ A BN asserting independence NOT present in Markov net → cannot always encode same distribution.

47. Independence via Structure — Quick Checks
  • Root nodes (no parents) in BN: independent of each other by default (if no common descendant observed)
  • Nodes in same clique of Markov net: generally dependent
  • Leaf nodes: always depend on their parents
  • Given all parents of X: X⊥{all non-descendants, all ancestors}
⚠ "Given parents" makes node independent of ancestors — but NOT necessarily independent of descendants!
⚠ "Not in each other's Markov Blanket" ≠ independent (could still have path through graph).
48. Exam Probability Calculation Checklist
  1. Write out full joint probability using BN chain rule
  2. Identify: Query var Q, Evidence vars E (fixed), Hidden vars H (sum over)
  3. Marginalize: P(Q|E) ∝ Σ_H P(Q,E,H) = Σ_H ∏ᵢ P(Xᵢ|Par(Xᵢ))
  4. Simplify using conditional independence if possible
  5. Normalize at end: P(Q=q|E) = unnorm_q / Σ_{q'} unnorm_{q'}
Ex. P(+b|+t,−m,−p) step-by-step:
Hidden: F. Evidence: T=+t, M=−m, P=−p. Query: B=+b.
P(+b|+t,−m,−p) ∝ Σ_F P(+b|F,−p)·P(F|+t,−m)
[T,M,P are given, so only F is hidden. B depends on F,P so factor P(B|F,P).]
= P(+b|+f,−p)·P(+f|+t,−m) + P(+b|−f,−p)·P(−f|+t,−m)
= 0.1·0.1 + 0.0·0.9 = 0.01
(No normalization needed since all other vars are fixed.)

49. Prior Sampling
PriorSample(BN): sample = {} for Xᵢ in topological order: sample[Xᵢ] ~ P(Xᵢ | sample[Parents(Xᵢ)]) return sample

Estimate P(Q=q) ≈ #samples_with_Q=q / total_samples. Cannot estimate P(Q|e) directly.

⚠ Prior sampling doesn't condition on evidence → only gives marginal (unconditional) estimates.
50. Rejection Sampling
Repeat: s ← PriorSample(BN) if s matches all evidence vars: KEEP else: REJECT (discard whole sample) P(Q=q|e) ≈ #kept_with_Q=q / #kept_total
⚠ Reject the entire sample if any evidence variable mismatches (not just that variable).
⚠ Stop early: once a variable conflicts with evidence during sampling, can discard immediately.
⚠ Extremely inefficient when evidence is rare (low probability).
Ex. HW3 Q10: P(D|B=0,E=1). BN: A→B→C,D→E. Order: A,B,C,D,E. Numbers: 0.426,0.348,0.584,0.913,0.637.
A: P(A=0)=0.3; 0.426≥0.3 → A=1.
B: P(B=0|A=1)=0.4; 0.348<0.4 → B=0 ✓ (evidence match, continue).
C: P(C=0|B=0)=0.5; 0.584≥0.5 → C=1.
D: P(D=0|B=0)=0.6; 0.913≥0.6 → D=1.
E: P(E=0|C=1,D=1)=0.9; 0.637<0.9 → E=0. Evidence E=1 → E REJECTED! Discard sample.
51. Likelihood Weighting (LW)
LWSample(BN, evidence e): w = 1.0; sample = {} for Xᵢ in topological order: if Xᵢ is evidence variable: sample[Xᵢ] = eᵢ // FIX to evidence value w *= P(eᵢ | sample[Par(Xᵢ)]) // multiply into weight else: sample[Xᵢ] ~ P(Xᵢ | sample[Par(Xᵢ)]) // sample freely return (sample, w) Estimate: P(Q=q|e) ≈ Σ{w : Q=q} / Σ{all w}
⚠ ONLY evidence variables contribute to weight. Non-evidence variables are sampled freely — their sampled value does NOT affect w.
⚠ If you accidentally sample an evidence variable instead of fixing it → biased estimate.
⚠ Evidence variable that appears BEFORE its parents in topo order: wait until parent sampled, then fix child and multiply P(child|sampled_parent) into weight.
Ex. F23: P(+b|+m). Sample (+t,+m,+f,+p,+b). Evidence = {M=+m}.
T: sample freely (no weight contribution). M: fix to +m; w *= P(+m)=0.1. F: sample freely. P: sample freely. B: sample freely. Weight = 0.1.
Ex. F24 Q5.2.1: P(A|+b,+c,+d). Evidence={B=+b,C=+c,D=+d}. Sample (+a,+b,−c,+d).
A: sample freely (A=+a). C: evidence, fix +c; but sample has C=−c → this sample conflicts with evidence C. Since we forgot to fix C and just sampled: C was sampled as −c, not fixed. This sample should be rejected (treat as rejection sampling for that variable). Weight for (+a,+b,+c,+d): w=P(+c)·P(+b|+a,+c)·P(+d|+a,+b)=0.3·0.65·0.60=0.117.
52. LW — Step-by-Step Guide
  1. List evidence variables and their values.
  2. Process variables in topological order.
  3. For each evidence variable: set to its value; w *= P(evidence_val | current_parent_values).
  4. For each non-evidence variable: sample from P(Xᵢ | current_parent_values). w unchanged.
  5. Collect (sample, weight).
  6. Repeat many times. Normalize to estimate P(Q|e).
Ex. HW3 Q5: P(C=1|B=1,E=1). BN: A→B→C,D→E. Order: A,B,C,D,E.
Evidence={B=1,E=1}. Numbers: 0.249,0.052,0.299,0.773,0.715,…
A: free. P(A=0)=0.2; 0.249≥0.2 → A=1. (use 0.249)
B: evidence=1. w*=P(B=1|A=1)=0.8. (no number used)
C: free. P(C=0|B=1)=0.1; 0.052<0.1 → C=0. (use 0.052)
D: free. P(D=0|B=1)=0.3; 0.299<0.3 → D=0. (use 0.299)
E: evidence=1. w*=P(E=1|C=0,D=0)=0.8. (no number)
Final w = 0.8×0.8 = 0.64. Sample: A=1,B=1,C=0,D=0,E=1.
53. Gibbs Sampling
GibbsSample(BN, evidence e, n_iters): // Initialize non-evidence vars to any value state = {e} ∪ {Xᵢ=random for non-evidence Xᵢ} samples = [] for i in 1..n_iters: pick non-evidence variable X to resample // Compute P(X | all other current values) // = P(X | MB(X)) ∝ P(X|par) × ∏_{Y∈Ch(X)} P(Y|par(Y)) resample X from this distribution state[X] = new value samples.append(state.copy()) return samples
⚠ Only non-evidence variables are resampled! Evidence stays fixed.
⚠ Use CURRENT values of all other variables (not initial values).
⚠ Must include ALL children of X in the product formula.
⚠ Always normalize the distribution before sampling!
54. Gibbs — P(X|MB) Computation
P(X=x | MB(X)) ∝ P(X=x | Parents(X)) × ∏_{Y ∈ Children(X)} P(Y=current | Parents(Y) with X=x)

Normalize over all possible values of X.

Ex. F23 Q5.2.3: Resample T. State=(+t,+m,+f,+p,+b). MB(T)={F,P,M}.
P(+t|+m,+f,+p) ∝ P(+t)×P(+f|+t,+m)×P(+p|+t,+m)
= 0.6×0.4×0.8 = 0.192
P(−t|+m,+f,+p) ∝ 0.4×0.8×0.2 = 0.064
Normalize: P(+t)=0.192/(0.192+0.064)=0.75.
Ex. F24 Q5.2.2: Resample D. State=(+a,−b,+c,+d). BN: A→B,C→B,A→D,B→D.
MB(D)=Parents(D)∪Children(D)∪CoParents = {A,B}∪{}∪{} = {A,B}.
D has no children → only multiply P(D|A,B).
P(+d|+a,−b) = 0.10; P(−d|+a,−b) = 0.90. Already normalized (parents fixed).
+d: 0.10, −d: 0.90.
Ex. HW3 Q9: Which Gibbs updates are INVALID?
Valid update: pick non-evidence variable, sample from P(X|MB(X)). Evidence vars are fixed (A=1,B=0,F=0).
Invalid: sampling B (evidence!) or using wrong parents/children in distribution.
Check: C's MB in given BN = {A,F,D,E}? Verify by structure. "C,P(C|A=1,F=0),C=1" is valid if C is non-evidence and {A,F} are indeed parents or MB of C. Valid ✓. "E,P(E|B=0,G=1),E=0" then G,P(G|E=1),G=0 valid if G is non-evidence. Check next update uses E=0 now (updated). Invalid update: one where distribution doesn't match true MB.

56. Master Trap List — Search & CSP
  • Minimax time = O(b^m), NOT O(b·m) or O(b·d). Space = O(bm).
  • UCS complete only when min arc cost > 0 (strictly positive).
  • BFS optimal only for unit/equal edge costs.
  • DFS: space O(bm), NOT O(b^m).
  • h(n)=0 is always admissible (never overestimates).
  • Consistent ⟹ Admissible. Admissible ⟹ Consistent is FALSE.
  • Admissible but not consistent + graph search → NOT guaranteed optimal.
  • Tree CSP: O(nd²), not O(n·d) or O(nd).
  • Arc (X,Y) in AC-3: removes values from X's domain. After revision of X, re-add (Z,X) for Z's neighbors of X.
  • MRV = variable with fewest domain values. LCV = value ruling out fewest for neighbors.
  • Genetic: selection → crossover first, mutation second.
  • Min-conflicts counts violated constraints in current full assignment.
  • Standard minimax fails on cyclic game graphs (loops).
  • Zero-sum: utilities are OPPOSITE, not independent.
  • Alpha-beta: order matters! Best order → O(b^(m/2)); reversed → fewer prunings.
  • Expectimax: changing probabilities → cannot reuse same pruning.
  • Coalition ≠ always benefit members individually.
57. Master Trap List — Logic
  • Valid = ALL models. Satisfiable = SOME models. Completely different!
  • Prove KB⊨α: add ¬α to KB, find □. NOT KB∨¬α.
  • FC = data-driven. BC = goal-driven. Reversed = exam trap.
  • Modus Ponens sound & complete for Horn ONLY, not general PL.
  • Horn clause: at most one positive literal (head can be absent too).
  • ∀ → ⇒; ∃ → ∧. Wrong choice → logically incorrect statement.
  • ∀x∃y ≢ ∃y∀x (quantifier order is NOT commutative).
  • ∀xP(x) ≡ ¬∃x¬P(x) → TRUE equivalent.
  • CNF final form: only ∧, ∨, ¬. No ⇒ or ⟺ allowed.
  • Atomic sentence: predicate(terms). No connectives inside. Functions return individuals (terms).
  • KB subset⊨α → KB⊨α. Adding facts cannot remove entailments.
  • Resolution: add ¬conclusion, derive □ for proof by contradiction.
58. Master Trap List — Bayesian Networks
  • Collider default = INDEPENDENT. Observed collider = DEPENDENT.
  • Observing collider's DESCENDANT also activates the path.
  • MB includes co-parents (other parents of X's children). Commonly missed!
  • VE factor size = 2^(#vars in factor) for binary. Order matters → affects max factor.
  • Polytree = no undirected cycles (stronger than DAG which just means no directed cycles).
  • LW weight = product of P(eᵢ|parents) for evidence vars ONLY.
  • Non-evidence sampled values do NOT affect LW weight.
  • Forgetting to fix evidence in LW → biased/inconsistent estimate.
  • Rejection sampling: reject ENTIRE sample on mismatch, not just that variable.
  • Gibbs: only resample NON-EVIDENCE variables. Evidence stays fixed.
  • Gibbs: always use CURRENT state of all other variables (not initial).
  • Gibbs: normalize the conditional distribution before sampling.
  • Markov net independence: purely graph-separation (no direction/d-sep complexity).
  • Markov net potentials ≠ probabilities (need Z for normalization).
  • BN→Markov net: moralize (marry co-parents), then undirect all edges.
